# Vulnerabilities the security gate (ci/scan.sh gate) lets pass for now, one per line:
#   <ID> <until YYYY-MM-DD> <why it is accepted and what will remove it>
# ID is a CVE, GHSA or Snyk id. The scanners still show it in their reports; after the date the gate blocks it again.
CVE-2016-1000027 2027-04-30 spring-web: Java deserialization in HttpInvokerServiceExporter, in every Spring 5 release. The fix is Spring 6 (Jakarta EE, Tomcat 10): a migration of the whole application. TravelAgency does not use HTTP Invoker or Java deserialization.
CVE-2026-47884 2027-04-30 spring-webmvc: SSRF and remote code execution through XsltView, when a "/**" mapping renders a view without an explicit view name. The only open-source fix is Spring 7.0.9 (5.3.50 is Enterprise Support only). TravelAgency renders only JSP (InternalResourceViewResolver): no XsltView, no "/**" view mapping.
CVE-2026-22732 2027-04-30 spring-security-web: Spring Security does not write its security headers (Cache-Control and others) when the application sets such headers itself. The open-source fixes are 6.5.9 and 7.0.4 (5.8.24 is Enterprise Support only). TravelAgency neither configures nor sets response headers itself.
CVE-2025-22228 2027-04-30 spring-security-crypto: BCryptPasswordEncoder.matches() accepts a password that shares the first 72 bytes with the stored one. The open-source fix is Spring Security 6 (5.8.18 is Enterprise Support only). TravelAgency hashes passwords with BCrypt, so this concerns only passwords longer than 72 bytes; removed by the Spring 6 migration, like CVE-2016-1000027.
